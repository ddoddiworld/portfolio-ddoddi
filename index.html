2022년, HTML과 jQuery로 화면을 그리던 퍼블리셔가 2026년에는 제휴 연동 플로우를 설계하고, 디자인 시스템을 만들고, 어드민 백엔드까지 다루는 프론트엔드 개발자가 되었습니다. 이 사이트는 그 4년의 기록입니다.

반려동물 헬스케어 플랫폼 인투펫과 동물병원 솔루션을 만드는 인투씨엔에스 개발3팀에서 일하고 있습니다. 올해는 10개 저장소에 약 1,170개 커밋을 남겼고, 그중 3개는 빈 레포에서 시작한 신규 구축이었습니다.

퍼블리셔에서 개발자로. 각 단계에서 무엇을 맡았고, 무엇이 달라졌는지 연도순으로 적었습니다.

  1. 20222021.09 – 2022.01Start

    웹 퍼블리셔 과정 수료, 클론·창작 사이트 5개

    HTML·CSS·jQuery로 반응형·적응형 홈페이지를 만들며 레이아웃과 인터랙션의 기본을 익혔습니다. 이 포트폴리오 사이트의 첫 버전도 이때 만들었습니다.

  2. 012026.01 – 02Solo build

    인투벳 클라우드 홈페이지 신규 구축

    빈 레포에서 Vue 3 + Vite 세팅, 10개 섹션 PC/모바일 퍼블리싱, 스크롤 애니메이션, 문의·뉴스 API, 다국어(KR/EN/JP), GA/GTM 전환추적까지 약 4주 동안 혼자 구축해 오픈했습니다.

    퍼블리싱이 끝이 아니라 유효성 검사·sanitize·전환 측정·OG 메타까지 갖춰야 운영 가능한 사이트가 됩니다. 이때 세운 구조 위에서 베트남어 추가, 첨부파일 문의, 번들 최적화를 그대로 흡수했습니다.

  3. 032026.03 – 07Systemize

    인투펫 어드민 v4 리뉴얼

    v2 어드민을 Nuxt 기반으로 재구축했습니다. 사이드바 13개 카테고리, 대시보드, 권한 그룹 시스템, 1:1 문의·FAQ·약관·광고&이벤트 관리를 구현하고 AdminTable·Tabs·StatusChip·SearchBar를 표준 컴포넌트로 뽑아 기존 페이지를 전수 마이그레이션했습니다. 광고&이벤트 관리는 배너 노출 로그까지 풀스택으로 구현했습니다.

    페이지를 빨리 만드는 것보다 페이지를 만드는 방법을 통일하는 것이 팀 전체 속도를 올립니다. 이 경험이 하반기 디자인 시스템으로 이어졌습니다.

  4. 032026.03 – 07Company face

    인투씨엔에스 홈페이지 2026 리뉴얼

    에이전시 정적 HTML을 Nuxt로 이식하고 20여 개 제품 페이지를 공통 컴포넌트로 통일했습니다. AI 소개 페이지는 시안 v1~v4를 직접 만들어 비교한 뒤 v5로 확정했고, ko/en 다국어·게시판·개인정보처리방침 API·SEO를 갖춰 6월 말 배포했습니다. 홈페이지 어드민의 게시판 동적 CRUD는 백엔드 엔티티·마이그레이션까지 직접 작업했습니다.

    큰 프로젝트일수록 한 번 잘 만들기보다 변경 비용을 낮추는 구조가 중요합니다. 배포 후 IntoPACS 개편이 페이지 단위로 빠르게 반영된 것이 그 증거였습니다.

  5. 072026.07 – 09Foundation

    인투펫 앱 v3 → v4 마이그레이션 기반 작업

    sass @use 전환, 루트 폰트 50%→100%와 rem 1/2 변환, Pretendard 셀프 호스팅, prettier 통합. 마이페이지·데일리케어·shortlink 130여 파일을 TypeScript로 전환하고 typecheck 노이즈를 641건에서 51건으로 줄였습니다.

    눈에 보이는 결과물이 없는 작업을 설득하고 끝까지 밀어붙이는 법. 이 바닥이 없었다면 바로 다음 181커밋짜리 연동을 같은 속도로 할 수 없었습니다.

  6. 072026.07 – 10Ownership

    네이버 플레이스플러스 펫수첩 연동

    네이버 제휴 동물병원의 내원내역을 인투펫 펫수첩으로 연동하는, 올해 가장 큰 외부 제휴 기능의 프론트 전체 플로우를 담당했습니다. 네아로 랜딩·비회원 가입·약관, 병원 선택·펫 매칭·연동/해지, AI 리포트 미리보기, 메인앱 진입점까지. 9월 17일 Beta를 오픈했습니다.

    기능을 구현하는 것과 출시하는 것은 다릅니다. 정책 변경, 외부 시스템의 예외, 배포 타이밍까지 포함해야 제품이 됩니다. 처음으로 담당자가 아니라 기능의 오너로 일했다고 느꼈습니다.

  7. 092026.09 – nowFor the team

    IDS 디자인 시스템과 셀러 포털

    커머스 어드민 두 개를 새로 만들어야 하는 상황에서, Figma 토큰 기준 공통 컴포넌트 31종과 아이콘 39종을 먼저 만들고 쇼케이스로 문서화했습니다. 그 위에서 셀러 포털 S-00~S-19 화면을 mock으로 먼저 퍼블리싱해 백엔드와 병렬로 진행하고, swagger가 나오는 대로 실연동하며 Playwright E2E를 작성하고 있습니다.

    1월에는 내가 빨리 만드는 법을 고민했고, 10월에는 팀이 빨리 만들게 하는 법을 고민합니다. 그 차이가 올해의 성장입니다.

Case 01

네이버 플레이스플러스 펫수첩 연동

2026.07 – 10 · 181 commits · Nuxt · TypeScript · shortlink + 메인앱 + IDS

플로우 다이어그램 · 화면 캡처 자리
Context
네이버 플레이스 제휴 동물병원의 내원내역을 인투펫 펫수첩으로 연동하는 신규 제휴 기능. 네이버 웹뷰, 아웃링크, OAuth(네아로), 앱 브릿지가 모두 얽혀 있었고 정책이 개발 중 여러 번 바뀌었습니다.
Role
프론트 전체 플로우 담당. 네아로 랜딩·비회원 가입·약관, 병원 선택·펫 매칭·연동 프로필 선택·완료/해지, AI 리포트 미리보기, 메인앱 마이페이지·펫 카드 진입점.
Problem
  • 백엔드 케이스 코드(4101~4106)에 따라 화면 분기가 전부 달라지고, swagger가 바뀔 때마다 따라가야 했습니다.
  • 아웃링크 복귀(returnTo/state), OAuth 콜백 재진입, 네이버 웹뷰 닫기 실패, 앱 미설치 등 우리 서비스 밖에서 일어나는 실패가 많았습니다.
  • 약관 동의 저장 시점, 해지 범위(전체 ↔ 펫별) 같은 정책이 출시 직전까지 바뀌었습니다.
Solution
  • 케이스 코드 기반 라우팅 테이블로 분기를 한곳에 모아 정책 변경 시 수정 범위를 좁혔습니다.
  • consume 토큰 1회용 소비, OneLink 폴백, 창 닫기 실패 시 고정 URL 이동 등 실패 경로마다 폴백을 두었습니다.
  • v3 mock → v4 이식 → 실연동 순서로 진행하고, 진입점 노출/비노출 배포 게이트를 반복 운영하며 인수인계 문서를 유지했습니다.

Case 02

인투씨엔에스 홈페이지 2026 리뉴얼

2026.03 – 07 · 267 commits · Nuxt · i18n · 어드민 백엔드 포함

제품 페이지 · AI 페이지 캡처 자리
Context
에이전시가 넘긴 정적 HTML을 Nuxt로 옮기고, 회사의 전 제품(EMR·PACS·LIS·결제·디바이스 등 20여 종)과 AI 소개 페이지를 하나의 사이트로 묶는 일. 올해 가장 많은 커밋이 들어간 프로젝트입니다.
Role
프론트 전체와 홈페이지 어드민(백엔드 포함). 제품 페이지 구조 설계, AI 페이지 시안 제작, 다국어, 게시판·정책 API 연동, 성능·SEO.
Problem
  • 제품마다 페이지가 제각각이어서 카피 한 줄 바꾸는 데도 페이지를 열어야 했습니다.
  • 원본 이미지가 85MB, 스크롤이 끊기고 GSAP/Lenis null 에러가 콘솔을 채웠습니다.
  • 게시판 종류가 하드코딩되어 운영자가 게시판을 추가할 수 없었습니다.
Solution
  • ProductHero·Features·Spec·StepFlow·SystemGrid 등 공통 컴포넌트로 20여 제품을 통일. 제품 추가는 데이터 추가로 끝나게 했습니다.
  • AI 소개 페이지 시안 v1~v4를 직접 만들어 비교한 뒤 v5 확정. 12종 모델 포트폴리오, 진료흐름 타임라인 구현.
  • WebP 전환, raf 이중 구동 제거, CSS 색상 :root 변수화(39개·456건), 미사용 i18n 키 221개 제거.
  • 어드민 게시판을 Board 엔티티·마이그레이션 → 관리 화면 → 사이트 노출 관계 → 레거시 컬럼 제거의 4단계로 동적 CRUD 전환.

어드민 화면 · IDS 쇼케이스 캡처 자리
Context
상반기에는 v2 어드민을 Nuxt v4로 재구축해야 했고, 하반기에는 커머스 어드민 두 개를 11월 말까지 새로 만들어야 했습니다. 두 번 다 "페이지마다 테이블·검색·버튼이 제각각"인 상태에서 시작했습니다.
Role
어드민 핵심 운영 화면 구현과 공통 컴포넌트 표준화. 하반기에는 admin 레포 분리, IDS 디자인 시스템 설계·구현·문서화, 셀러 포털 퍼블리싱.
Problem
  • 수십 개 페이지의 UI 규칙이 달라 운영자 학습 비용과 개발 수정 비용이 함께 컸습니다.
  • 새 어드민을 같은 방식으로 만들면 같은 문제가 두 배로 생길 것이 뻔했습니다.
Solution
  • 어드민 v4: AdminTable·Tabs·StatusChip·SearchBar·공용 모달을 표준으로 뽑고 전 페이지 마이그레이션. alert → useModal, 스타일 외부 분리, 다크모드 토큰화. 권한 그룹 시스템(메뉴 카탈로그·매트릭스·라우트 가드)과 광고&이벤트 풀스택 구현.
  • IDS: Figma Color/Typography 토큰 기준 컴포넌트 31종·아이콘 39종을 먼저 만들고 쇼케이스 페이지와 정본 문서로 공유. 금액·마스킹·KST 유틸과 vitest 검증, 공용 useApi 레이어.
  • 셀러 포털 S-00~S-19를 IDS로 mock 퍼블리싱해 백엔드와 병렬 진행, swagger 확정 순서로 실연동.
